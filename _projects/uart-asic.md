## 项目目标

独立完成一颗串口通信芯片从 **RTL 设计到 GDSII 版图**的数字 IC 实现流程。功能核心是 115200 bps UART 收发，并通过 64-Byte FIFO 缓冲数据。项目不仅要求逻辑功能正确，还要经过综合、布局布线、时钟树、时序分析和物理验证。

## 前端设计

UART 模块负责串行数据的起始位、数据位和停止位处理，发送与接收路径通过 FIFO 解耦上层读写速度和串行接口速率。RTL 阶段重点检查波特率计数、采样时刻、状态机跳转、FIFO 满空边界以及复位后的初始状态。

使用 Design Compiler 进行逻辑综合，并在拓扑模式下加入物理约束，使综合阶段能够更接近后端连线和布局条件。综合结果作为后续物理实现的网表输入。

## 后端实现

- 完成 floorplan、标准单元布局与布线流程。
- 在 M5/M6 构建双层电源网格，为标准单元提供稳定的电源分布。
- 构建三级缓冲平衡时钟树，控制时钟插入延迟与分支差异。
- 根据建立和保持时间报告进行增量优化，处理关键路径与短路径问题。
- 完成 DRC 和 LVS 检查，确认几何规则与网表连接一致后导出 GDSII。

## 签核结果

| 指标 | 结果 |
| --- | ---: |
| UART 速率 | 115200 bps |
| FIFO 深度 | 64 Byte |
| 全局时钟偏差 | 0.09 ns |
| Setup 余量 | +9.77 ns |
| Hold 余量 | +0.046 ns |
| 功耗 | 0.23 mW |
| DRC / LVS | 0 错误 |

这些数据来自该项目已有记录。正余量表示在对应约束下没有建立或保持时间违例；DRC/LVS 零错误表示版图通过当前规则文件和网表的一致性检查。

## 项目收获

项目把 RTL 编码、约束、综合和物理实现连接为一条完整流程。前端结构会直接影响面积、功耗和时序，后端问题也可能要求回到 RTL 或约束重新分析。相比只观察功能仿真，完整芯片实现更强调约束可信、报告可解释和每个阶段结果可交接。
